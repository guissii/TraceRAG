Retrieval-Augmented Generation (RAG) : Architecture et Principes

Introduction
La Retrieval-Augmented Generation (RAG) est une architecture hybride qui combine la puissance des modèles de langage (LLM) avec la précision d'un système de recherche documentaire. Contrairement aux LLM classiques qui s'appuient uniquement sur leur mémoire paramétrique, un système RAG ancre ses réponses dans des sources factuelles vérifiables.

Architecture en Pipeline
Le pipeline RAG se décompose en deux phases principales :

Phase A - Indexation :
1. Extraction : Les documents (PDF, TXT, DOCX) sont convertis en texte brut à l'aide de bibliothèques spécialisées comme PyMuPDF. Cette étape inclut le nettoyage des artefacts de formatage et la normalisation Unicode.

2. Chunking Sémantique : Le texte extrait est divisé en segments de taille optimale (chunks). Notre système utilise une fenêtre de 400 mots avec un chevauchement (overlap) de 60 mots pour préserver le contexte inter-phrase.

3. Embedding Vectoriel : Chaque chunk est transformé en un vecteur de 384 dimensions par le modèle neuronal all-MiniLM-L6-v2. Ce processus capture le sens sémantique profond du texte, permettant des comparaisons mathématiques de similarité.

4. Stockage ChromaDB : Les vecteurs et métadonnées associées sont stockés dans une base de données vectorielle ChromaDB, optimisée pour la recherche K-NN (K-Nearest Neighbors) via l'algorithme HNSW (Hierarchical Navigable Small World).

Phase B - Interrogation :
1. Requête et Embedding : La question de l'utilisateur est convertie dans le même espace vectoriel de 384 dimensions, créant ainsi un point de comparaison.

2. Retrieval HNSW : Le moteur projette le vecteur de la question dans l'espace ChromaDB et récupère les Top-K chunks les plus similaires en utilisant la distance cosinus.

3. Augmentation du Prompt : Les chunks récupérés sont assemblés avec la question originale dans un prompt structuré, avec des instructions système strictes pour contrôler les hallucinations.

4. Génération LLM : Le modèle de langage (phi3 via Ollama) effectue l'inférence locale en synthétisant le contexte fourni pour produire une réponse factuelle et sourcée.

Avantages Technologiques
- Traçabilité complète : Chaque étape du pipeline est chronométrée et visualisée
- Contrôle des hallucinations : Le LLM est contraint de répondre uniquement à partir du contexte fourni
- Embedding normalisé L2 : Garantit des comparaisons de similarité précises
- Batch processing : Optimisation des performances pour les large documents
- Architecture modulaire : Backend FastAPI + Frontend SPA avec visualisations interactives

Conclusion
TraceRAG représente une approche pédagogique unique qui rend visible et compréhensible chaque transformation dans le pipeline RAG, de l'ingestion du document brut jusqu'à la génération de la réponse finale.
